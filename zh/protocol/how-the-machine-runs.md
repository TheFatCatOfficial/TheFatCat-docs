# 机器如何运转

本章根据创始人 Silas 的同名文章整理，将交易税收入、Belly 储备、质押资历、食谱选择与 FEED 维护串成一条完整流程。阅读后，你可以理解一笔收入如何成为仓位奖励，以及每一步需要哪些条件。

## 1. 从交易税到仓位奖励

TheFatCat 用 Belly 蓄积收入，再按餐次和仓位权重分配。质押本金、奖励储备与待领奖励分别记账和托管。

| 阶段 | 发生什么 | 对用户意味着什么 |
|:---|:---|:---|
| 税收接收 | FATCAT 的交易税经上游路径以 QQQB 接收，之后兑换成 WBNB | 成交产生税收，不代表收入已经进入 Belly；变现与兑换仍需成功执行 |
| 收入分账 | 扣除上游费用及适用的 FEED 奖励后，净收入的 85% 连同分账取整余数进入 Belly，15% 用于开发、运营和营销 | 85% / 15% 的基数是扣费、扣奖后的净收入 |
| 餐次分配 | 成功推进餐次时，协议从未预留资金中记录本餐预算和仓位权益 | 分配是记账，此时没有把奖励转入你的钱包 |
| 资产结算 | 执行器按餐次顺序采购所选资产，或按规则以 WBNB 回退结算 | 奖励可能等待价格、流动性、维护或金库额度条件 |
| 用户领取 | 已结算奖励进入分发器，你通过领取交易提取 | 领取与质押本金赎回是独立操作 |

普通质押本金保存在独立 Vault 中。领取奖励交付的是已结算的奖励资产，不会卖出你托管的 FATCAT 本金。完整费用口径见[税收路由与费用]({% link zh/protocol/fees.md %})。

## 2. Belly 为什么像一个蓄水池

交易活跃时，手续费可能集中流入；Belly 将这段收入分配到后续餐次。它改变收入的分配节奏，但不能创造额外收入。

在完整计奖、满足分配条件且准时推进的八小时餐次中，预算上限为**未预留计价资金的 1/21，约 4.76%**。已为待结算餐次预留的资金不再参与这一计算，避免重复分配。

- 餐次至少间隔八小时，需要有人提交成功交易才会推进。
- 一次推进只关闭一餐，下一餐从本次调用时刻开始，不补齐错过的历史餐次。
- 推进延迟时，最多计入十六小时的有效奖励时间。
- 初始积累期、有效权重不足、资产限额与整数舍入都可能使实际分配低于预算上限。

假设没有新增收入、每八小时准时关闭一个有效餐次、分配完整且及时执行，并忽略整数尘埃，模型中的未预留余额会按以下比例衰减：

| 经过时间 | 模型中的剩余未预留余额 |
|:---|:---|
| 1 天 | 约 86% |
| 3 天 | 约 64% |
| 7 天 | 约 36% |
| 14 天 | 约 13% |
| 30 天 | 约 1.24% |

这一理想模型的半衰期约为 4.74 天。表格描述预算分配模型；尚未结算的预留仍可能留在 Belly，因此不能把它直接当作实际金库余额或个人到账时间表。没有新收入，每餐可分配金额也会逐渐缩小。

实际资金流出另受独立的八小时窗口限额约束。分配预算和提款额度是两套规则，详见[Belly 储备与释放机制]({% link zh/protocol/belly.md %})。

## 3. 仓位如何记录本金与时间

每次质押建立一个独立仓位，分别记录本金、资历、食谱与领取进度。同一钱包可以拥有多个仓位，它们不会自动合并。普通仓位的最低本金为 **100,000 FATCAT**；门槛在部署时固定，其市场成本随 FATCAT 价格变化。

仓位权重的基本关系是：

**仓位权重 = 质押本金 × 时间乘数**

新仓位不参与已经开启的餐次，从下一餐以 **1×** 生效。此后每完成一个活跃餐次，乘数增加 1，完成 21 个活跃餐次后达到 **22×** 上限。这里计数的是实际推进的餐次；等待日历时间不会自动增加资历，也不会让本金产生复利。

例如，两个本金均为 100,000 FATCAT 的仓位，首次活跃仓位的权重为 100,000，成熟仓位为 2,200,000。二者的单位本金权重相差 22 倍，但实际奖励还取决于全池权重、食谱分配与执行结果。若所有仓位都已成熟，单位本金权重相同，份额重新按本金比例决定。

同资历下，十倍本金仍对应十倍权重。时间权重不会限制大额本金，新资金从下一餐开始也可能稀释其他仓位的后续份额。公式与边界见[餐次与资历]({% link zh/protocol/meals-and-seniority.md %})。

### 最初七天如何计算

代币毕业后将马上开放质押。初始七天积累期从**成功开放质押的交易**开始，该交易启动奖励时钟。期间可以在成功推进的餐次中积累资历，但不分配新的奖励预算；成功兑换的收入留在 Belly。

这也是为什么“已经开放七天”和“已完成 21 个活跃餐次”不能互换。积累期结束后，仍需成功推进餐次，并满足有效计奖时间、权重与分配条件，才会形成奖励预算。

## 4. 食谱决定奖励以什么资产结算

每个仓位从已启用的菜单中选择一项 DIET。BNB 是默认选择，内部以 WBNB 记账，无需额外采购交易，并可在领取时解包为原生 BNB。符合条件的菜单还可包含股票代币（bStocks）等资产；FATCAT 自身须在毕业、路由验证和 TWAP 预热等条件满足后才可能加入。

- 更换食谱从下一餐生效，不重置时间资历，也不收取协议切换费；交易仍需 Gas。
- 旧食谱下已记录的奖励保留，更换食谱不会把它们重新兑换成新资产。
- 非 WBNB 资产的采购按全局最早餐次顺序推进，须通过价格、流动性、最小输出等检查。
- 满足回退条件的分配可以 WBNB 结算，但仍需要可用资金和金库额度；一次采购失败不意味着立即完成回退。

分配、结算和领取可以发生在不同时间。操作方法见[食谱与领取]({% link zh/guides/diets-and-claiming.md %})，等待与回退规则见[采购与执行]({% link zh/protocol/execution.md %})。

## 5. 谁让机器继续运转：FEED

智能合约需要交易触发。任何人都可以尝试公开维护，不要求每位质押用户运行维护程序。一次 FEED 会依次尝试：

1. 将税收金库中的 QQQB 兑换为 WBNB，并转发收入。
2. 推进至多一个已到期餐次，记录新的分配。
3. 检查合约指定的一批菜单资产，尝试执行待结算采购。

操作人支付 Gas，不需要拿自己的 QQQB 兑换。各步骤仍受余额、时间、价格、流动性和暂停状态等条件约束。

### FEED 奖励如何产生

在 FEED 成功兑换的时刻，原始调用者须满足以下条件之一：持有至少 **10,000 FATCAT**，或提供一个属于自己且剩余质押本金大于零的仓位。满足资格时，奖励按本次实际 WBNB 总产出的 1/38，向下取整 记账。不满足资格仍可帮助维护，但不获得这笔奖励。

奖励记为可单独领取的 WBNB，需要另一笔交易及 Gas 提取。单独推进餐次、采购，或没有成功兑换的 FEED 扫描，都不产生此奖励。忽略费用、价格变化和取整时，它才在标准税率模型下约等于对应交易额的 0.1%；实际金额以兑换与奖励记录为准。

后续推进或采购的局部失败通常不会撤销已经成功的兑换和合资格奖励，但无效输入、整笔交易 Gas 耗尽等情况仍可能使整笔交易回滚。成功回执也不代表所有步骤都完成了。官方自动维护会尝试补充推进，其成功与及时性仍依赖执行条件和运行环境。详见[FEED 与去中心化维护]({% link zh/guides/community-keeper.md %})。

## 6. 退出时哪些权益会保留

普通仓位没有协议锁定期或退出费。赎回返回本金，并结束该仓位的未来计权；退出会放弃当前仍在进行的餐次权益，此前已记录的奖励权益保留。新建普通仓位重新从 1× 开始。

| 资金所在位置 | 作用与边界 |
|:---|:---|
| 质押 Vault | 保管本金；普通赎回不检查协议暂停标记 |
| Belly | 保管奖励储备；流出受固定路由、暂停与窗口限额约束 |
| 奖励分发器 | 保管已结算奖励；领取不依赖 Belly 当时能否继续出流 |

因此，待采购奖励延迟或 Belly 暂停，不会给普通赎回新增一个餐次等待要求。实际赎回和领取仍须交易成功、代币正常交付，并通过相应合约检查。前端不可用时的直接交互方法见[紧急退出说明]({% link zh/guides/emergency-exit.md %})。

## 7. 理解规则后，还需要关注什么

奖励来源于实际收入及可被合约识别的捐入资金，取决于交易量、参与本金与资历分布、所选资产和执行结果。蓄水池与时间权重不能保证固定收益。

上游 Flap 权限可能改变未来税收路由；股票代币另有发行方、托管与升级风险；TWAP 检查不能消除市场操纵、MEV 或流动性风险。查看[风险边界]({% link zh/safety/risks-and-status.md %})，了解这些条件如何影响你的操作；[运行监控与应急响应]({% link zh/safety/monitoring.md %})概述异常处置措施。

[时间资历凭证]({% link zh/guides/seniority-certificates.md %})属于未来路线图，将在协议成熟时推出，并以 NFT 的形式留存。持有质押仓位的用户可燃烧 FATCAT 进行铸造，详细内容会在后续公布。
