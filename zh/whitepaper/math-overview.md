# 机制摘要

本页概述储备分配、仓位权重和奖励领取规则。模型结果依赖明确的假设，不是付款时间表。

## 分配与执行

正常八小时餐次最多分配未预留资金的 1/21。延迟推进最多计入 16 小时的有效分配时长。分配只登记保留资金，实际流出另外受到 Belly 窗口额度约束。详见 [Belly 规则]({% link zh/protocol/belly.md %})。

约 4.736 天的半衰期适用于理想模型：没有新流入、每八小时分配并完成结算、无暂停或积压，并忽略舍入。它不是付款时间表。

## 资历

仓位权重 = 本金 × 时间资历系数 × 所选资产的激励系数，普通生效仓位从 1× 升至 22×。在标准八小时节奏下，从 1× 升至 22× 需要完成 21 个活跃餐次，约七天；维护延迟会延后晋升。参与规则见[餐次规则]({% link zh/protocol/meals-and-seniority.md %})。

各资产选项的激励系数分别设置，初期由官方调控，取值范围 1.0×–2.0×。公布调控并上线后，经三天治理等待后从下一餐生效。

## 资产与领取

每个仓位按所选食谱资产接收奖励。以 WBNB 计价的分配、资金已到位的奖励数量和可领取金额属于不同阶段；采购执行及有条件的 WBNB 回退决定可领取资产。采购按[全局餐次顺序]({% link zh/protocol/execution.md %})推进。已结算奖励不会因用户迟迟未领取而被收回。

## 核算边界

向下取整约束资金已到位批次的支付，不证明任意代币的安全性或市场价值。为待采购份额预留的资金，与已为用户结算的奖励分别记录。详见[核算约束]({% link zh/definitions/invariants.md %})、[托管]({% link zh/safety/custody.md %})和[风险边界]({% link zh/safety/risks-and-status.md %})。
